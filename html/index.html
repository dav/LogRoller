LogRoller

Allow your code agent to directly access debug logs when you are testing code on remote devices.

What is LogRoller?

LogRoller allows your code agents to check the logs for your manual or automated test runs that are happening on a different device, e.g. an iPhone or Vision Pro, so you can tell the agent to check logs on your recent test run to help debug what went wrong.

LogRoller runs a lightweight HTTPS server on your Mac that receives structured events from any client — iOS simulators, physical devices, or desktop apps. Events are persisted locally as NDJSON and queryable via the logroller CLI, making it easy for AI agents and human developers to inspect what happened during a test run.

Local HTTPS Ingest

TLS-secured server on port 8443. Clients POST structured events with run and device identifiers.

CLI Query Tool

The logroller CLI queries events by run, device, and level. Outputs JSON or NDJSON for piping into other tools.

Claude Code Skill

Includes a skill that teaches AI agents how to wire client logging to LogRoller — endpoints, batching, retry, and verification.

Zero Dependencies

Pure Swift. No third-party frameworks. Uses Network.framework for the server and Foundation for storage.

Using with Claude Code

The install script adds a Claude Code skill that teaches the agent how to integrate client logging with LogRoller. In any project, ask Claude to: 

Wire this app to send events to LogRoller

The agent will use the skill to discover the ingest contract, implement the client, and verify events are flowing.

Later when you and Claude have deployed new code to your test device and something has gone wrong, you can tell Claude: 

Something went wrong, can you check the logs for the last test run?

Claude will then be able to research the issue directly even though it does not have diredct access to the device logs.
