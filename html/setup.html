Setup Guide

Get LogRoller running on your Mac in a few minutes.

Prerequisites

  • macOS 15+ (Sequoia or later)
  • Claude Code installed and authenticated (for the integration skill)
  • LogRoller DMG — download here

1 Download and Install

Download LogRoller.dmg.zip

Unzip the download and open the DMG:

unzip LogRoller.dmg.zip
open LogRoller.dmg

The DMG contains LogRoller.app, the logroller CLI binary, a Claude Code skill file, and an install script. You can either:

  • Drag and drop — drag LogRoller.app to the Applications symlink in the DMG, then manually copy the CLI and skill (see step 2).
  • Run the install script — this does everything automatically (see below).

2 Run the Install Script

With the DMG mounted, open Terminal and run:

bash /Volumes/LogRoller/install.sh

The install script will:

  • Copy LogRoller.app to /Applications/
  • Copy the logroller CLI to ~/bin/
  • Install the Claude Code skill to ~/.claude/skills/logroller-client-integration/

Make sure ~/bin is in your PATH. If not, add it to your shell profile: 

# For zsh (default on macOS):
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.zshrc

# For fish:
fish_add_path ~/bin

3 Launch LogRoller

Open LogRoller from /Applications. The app starts an HTTPS server on port 8443 that listens for incoming events. The server runs in the background even when the window is closed.

You won't really need to interact with the LogRoller GUI much. The point of this system is really just to give your code agents access to the CLI commands so they can check logs themselves without you needing to copy/paste info for them.

4 Verify Everything Works

Open a new terminal and run these checks:

Server status: logroller status — should show "server_active": true
Ingest contract: logroller ingest-help — shows the endpoint, required fields, and cURL examples

Send a test event

curl -sk https://localhost:8443/ingest \
  -H "Content-Type: application/json" \
  -d '[{
    "run_id": "test-run",
    "device_id": "my-mac",
    "event_type": "log",
    "level": "info",
    "message": "Hello from LogRoller"
  }]'

Query the event

logroller events --run test-run --json

You should see the event you just sent, with a timestamp and the fields you provided.

Using with Claude Code

The install script adds a Claude Code skill that teaches the agent how to integrate client logging with LogRoller. In any project, ask Claude to: 

Wire this app to send events to LogRoller

The agent will use the skill to discover the ingest contract, implement the client, and verify events are flowing.

Later when you and Claude have deployed new code to your test device and something has gone wrong, you can tell Claude: 

Something went wrong, can you check the logs for the last test run?

Claude will then be able to research the issue directly even though it does not have diredct access to the device logs.

Troubleshooting

"Connection refused" from logroller status

The LogRoller app isn't running. Launch it from /Applications and wait a few seconds for the server to start.

Certificate warnings from curl

LogRoller uses a self-signed TLS certificate. Use the -k flag with curl to skip verification, or set up mkcert for trusted local certificates.

CLI not found

Make sure ~/bin is in your PATH and restart your terminal (or run source ~/.zshrc).
